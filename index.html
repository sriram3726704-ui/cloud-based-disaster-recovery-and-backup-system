Core Disaster Recovery Principles (For Faculty Viva)

1. Recovery Point Objective (RPO): The maximum acceptable age of files that must be recovered from backup storage for normal operations to resume. CloudVault ensures continuous cloud syncing to keep RPO close to zero.
2. Recovery Time Objective (RTO): The maximum acceptable duration of time that can elapse after a disaster before systems and files are fully restored. CloudVault achieves RTO under 5 seconds through direct cloud streaming.
3. The 3-2-1 Backup Strategy: Keep at least 3 copies of data, across 2 different media types, with 1 copy stored off-site in the cloud.
⚠️ Critical Recovery Notice: Deleted backups cannot be restored unless an independent external snapshot was exported. Once permanently deleted from Cloud Storage, the file blocks are unrecoverable.

Security Rules & Architecture

Review server-side access controls, user isolation, and Firebase rules configuration.

Firestore Security Rules (firestore.rules)
Enforced

Ensures only authenticated users can read or write documents where userId == request.auth.uid. 

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /backups/{backupId} {
      allow create: if request.auth != null 
                    && request.resource.data.userId == request.auth.uid
                    && request.resource.data.fileSize <= 26214400;
      allow read, update, delete: if request.auth != null 
                                  && resource.data.userId == request.auth.uid;
    }
    match /activity_logs/{logId} {
      allow create, read: if request.auth != null 
                          && request.resource.data.userId == request.auth.uid;
      allow update, delete: if false; // Append-only audit log
    }
  }
}
Storage Security Rules (storage.rules)
Enforced

Strict folder isolation preventing users from reading or writing into another user's storage path. 

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /users/{userId}/{allPaths=**} {
      allow read, delete: if request.auth != null 
                          && request.auth.uid == userId;
      allow write: if request.auth != null 
                   && request.auth.uid == userId
                   && request.resource.size < 25 * 1024 * 1024;
    }
  }
}

College Project Viva & Presentation Guide

1. Project Summary for Faculty

"CloudVault" is a Cloud-Based Disaster Recovery and Backup System designed to protect critical enterprise documents from hardware failure, accidental deletion, and ransomware. It uses Firebase Authentication for secure multi-tenant user isolation, Cloud Storage for redundant file replication, and Firestore for metadata tracking and tamper-proof audit trails.

2. Frequently Asked Viva Questions

Q1: What is the difference between RPO and RTO?

RPO (Recovery Point Objective): How much data loss can be tolerated (in time). CloudVault keeps RPO < 1 hour by providing continuous uploads.
RTO (Recovery Time Objective): How fast data can be recovered after a disaster. CloudVault achieves RTO < 5 seconds via high-speed cloud download streams.

Q2: How is security and user isolation enforced?

Security is enforced at two levels: First, client-side validation prevents oversized (>25MB) or disallowed files. Second, server-side Firestore and Storage Security Rules check request.auth.uid == userId to strictly ensure no user can ever access or delete another user's backups.

Q3: Why can't a deleted file be restored?

When a user deletes a backup, CloudVault calls Firebase Storage's deleteObject() API, releasing the cloud storage blocks to optimize costs. Hence, in disaster recovery principles, deleted files cannot be restored unless a secondary immutable snapshot or versioning bucket policy is preserved.
